## Sequence (mirrors the standing playbook)

1. Snapshotted both DBs (`wwf_users`/`wwf_tasks`, `/opt/wwf-deploy/snap/`),
   verified `gzip -t` + dump-complete marker on both.
2. Confirmed no migration needed (heads already matched).
3. Owner supplied a classic PAT (`repo` scope); staged to a `chmod 600` file,
   used only for the Docker daemon's git-context clone, `shred -u`'d
   immediately after each build round — including a first, unused fine-grained
   token that hit `403: Write access to repository not granted` (fine-grained
   tokens need explicit per-repo + per-permission configuration; classic
   tokens don't have that failure mode) — both revoked by the owner after.
4. Built all three images from `ddc68f4` via the proven git-build-context
   method, in parallel, backgrounded with `nohup setsid` + a status file so no
   tool-call timeout could orphan them. All three: exit 0.
5. Asserted the built backend image's alembic heads against production —
   matched exactly, confirming step 2.
6. Backed up `compose.yaml` (`compose.yaml.bak-pre-v89v129v20-20260824`),
   `sed`-bumped the four image-tag lines, validated with `docker compose
   config`.
7. Recreated one service at a time, `--no-deps`, verifying health after each:
   backend → scheduler → frontend → docengine. No DB service touched, no
   `down`, no volume pruned.
