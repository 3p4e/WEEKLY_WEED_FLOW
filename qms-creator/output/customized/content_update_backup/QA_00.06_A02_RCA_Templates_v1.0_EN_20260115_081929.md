## PURPOSE

This annex provides five detailed templates and worksheets for conducting structured Root Cause Analysis (RCA) investigations. These templates support systematic identification of fundamental causes of quality issues, enabling development of effective corrective and preventive actions.

### Instructions:

1. Write the problem in the head (right side) of the fishbone diagram
2. Identify the 6 main cause categories (Major Bones):
   - **People**: Personnel competency, training, awareness, communication
   - **Process**: Procedures, controls, critical parameters, work instructions
   - **Plant**: Equipment, tools, facilities, environment conditions
   - **Materials**: Starting materials, specifications, supplier quality
   - **Methods**: Analytical techniques, sampling, data recording procedures
   - **Environment**: Temperature, humidity, utilities, external factors
3. For each category, brainstorm specific contributing causes (Minor Bones)
4. Analyze: Which factors contributed to the observed problem?
5. Circle or highlight the most likely root causes

### Step 3: Trend Analysis

**Describe the pattern of data over time:**

☐ **STABLE** - Values are randomly scattered around mean, no clear trend
   - Expected: Normal variation within specification

☐ **INCREASING TREND** - Values systematically increasing over time
   - Possible causes: Equipment degradation, process drift, aging materials, wear

☐ **DECREASING TREND** - Values systematically decreasing over time
   - Possible causes: Equipment performance improvement, procedure refinement, learning

☐ **CYCLICAL PATTERN** - Values increase/decrease in repeating cycle
   - Possible causes: Time-of-day effect, shift effect, environmental cycle, weekly pattern

☐ **SUDDEN SHIFT** - Values shift to higher/lower level at specific date
   - Possible causes: Equipment change, procedure change, supplier change, personnel change

☐ **HIGH VARIABILITY** - Values scatter widely with no clear pattern
   - Possible causes: Multiple uncontrolled factors, inadequate process controls, sampling issues

### Fault Tree Diagram Instructions

A Fault Tree Analysis decomposes a complex failure (Top Event) into progressively simpler contributing causes, creating a logic tree showing how individual failures combine to cause the top event.

**Symbols Used:**
- **OR Gate** (∨): Failure occurs if ANY input causes occurs
- **AND Gate** (∧): Failure occurs only if ALL input causes occur simultaneously
- **Intermediate Event**: A failure that results from combination of causes
- **Basic Event**: A fundamental failure that cannot be further decomposed

---

### Fault Tree Diagram Structure

```
                                    TOP EVENT
                                   (The Problem)
                                        │
                                        │ OR GATE
                    ┌───────────────────┼───────────────────┐
                    │                   │                   │
            Intermediate           Intermediate         Intermediate
            Event 1                Event 2               Event 3
                    │                   │                   │
                 OR GATE            OR GATE               OR GATE
            ┌────────┴────────┐  ┌────────┴────────┐  ┌────────┴────────┐
            │                 │  │                 │  │                 │
        Basic Event 1     Basic Event 2      Basic Event 3      Basic Event 4
        (Cannot prevent)  (Can control)      (Cannot prevent)   (Can control)
```

## GENERAL NOTES FOR ALL RCA TEMPLATES

### When to Use Each Method:

**Use 5 Whys When:**
- Issue is relatively simple
- Single root cause is likely
- Quick analysis needed
- Team has limited RCA experience

**Use Fishbone When:**
- Multiple factors may have contributed
- Issue is moderately complex
- Cross-functional perspective needed
- Need to ensure comprehensive coverage

**Use Statistical Analysis When:**
- Quantitative data available
- Process variation involved
- Trend or pattern analysis helpful
- Root cause may be subtle or time-dependent

**Use Brainstorming When:**
- Root cause uncertain or unclear
- Multiple expert perspectives valuable
- Creative problem-solving needed
- Team engagement important

**Use Fault Tree When:**
- System is complex with multiple interconnections
- Multiple failure pathways possible
- Logic of failure sequence important
- Detailed failure analysis needed

### Quality Standards for All RCA:

All RCA investigations, regardless of method used, **MUST demonstrate:**

✓ **Factual** - Based on evidence, not speculation
✓ **Complete** - Addresses all aspects of problem, not just immediate cause
✓ **Causal** - Explains WHY problem occurred, not just WHAT happened
✓ **Systemic** - Identifies underlying organizational causes
✓ **Preventable** - Identifies factors that could have been controlled
✓ **Logical** - Clear reasoning from evidence to conclusions

### Evidence Standards:

For each identified root cause, you should have:
- **Objective Evidence**: Data, documents, records supporting the cause
- **Testimony**: Statements from personnel involved (if applicable)
- **Analysis**: Logical connection between evidence and conclusion

**Example:**
- ❌ "Equipment was not working properly" (vague, no evidence)
- ✅ "Analytical balance (ID: LAB-2024-001) was not calibrated since 2023-06-15, exceeding the 12-month calibration interval. Calibration certificate from 2026-01-22 shows last successful calibration. Batch record shows balance used on 2024-01-20, 7 months after calibration due. Environment record shows scale located in uncontrolled environment with temperature fluctuations." (specific, evidence-based)
