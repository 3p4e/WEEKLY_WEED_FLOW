# ANNEX A01: DOCUMENT TEMPLATE STANDARDS

**Parent SOP:** QA_00.02_A01_v1 Document Control
**Annex Code:** QA_00.02_A01_v1
**Version:** 1.0
**Effective Date:** 2026-01-22

---

## PURPOSE

This annex defines the standardized templates to be used for all GMP documents within the Quality Management System of Purely Plant Medical Cannabis Production Facility, ensuring consistency, regulatory compliance, and ease of use.

---

## 1. STANDARD OPERATING PROCEDURE (SOP) TEMPLATE

### 1.1 Required Header Elements

```
STANDARD OPERATING PROCEDURE

Document Code: [CHAPTER]-Master Documents-[XXX]
Title: [Descriptive Title]
Version: [X.X]
Effective Date: [DD-MMM-YYYY]
Review Date: [DD-MMM-YYYY + 24 months]
Supersedes: [Previous version or N/A]
```

### 1.2 Approval Signature Block

```
APPROVAL SIGNATURES

| Role | Name | Signature | Date |
|------|------|-----------|------|
| Prepared by: | [Name] | ____________ | ________ |
| Reviewed by: | [Name] | ____________ | ________ |
| Approved by: | [Name] | ____________ | ________ |
```

### 1.3 Required Sections

1. **Purpose** - Why this SOP exists (2-3 sentences)
2. **Scope** - What/who it applies to; what it excludes
3. **Responsibilities** - Who does what (by role)
4. **Definitions** - Key terms used in the SOP
5. **Procedure** - Step-by-step instructions (numbered)
6. **References** - Regulatory basis, related SOPs
7. **Annexes** - Supporting documents/forms (if applicable)
8. **Revision History Table**

### 1.4 Formatting Standards

- **Font:** Arial 11pt for body text, Arial 14pt Bold for main headings
- **Margins:** 2.5cm top/bottom, 2.0cm left/right
- **Line Spacing:** 1.15 lines
- **Page Numbers:** Footer right-aligned: "Page X of Y"
- **Headers:** Include Document Code and Title
- **Section Numbering:** Hierarchical (1.0, 1.1, 1.1.1)
- **Language Style:** Imperative mandatory ("shall," "must")
- **Tense:** Present tense
- **Voice:** Active voice preferred

## 2. FORM TEMPLATE

### 2.1 Required Header Elements

```
Purely Plant Medical Cannabis Production Facility
[Form Title]

Form Code: [CHAPTER]-Master Documents-[XXX]-F[Form Number]
Version: [X.X]
Effective Date: [DD-MMM-YYYY]
Related SOP: [SOP Code]
```

### 2.2 Form Design Requirements

- Clear field labels
- Adequate space for entries (minimum 2 lines for text fields)
- Checkbox options where applicable
- Signature/date blocks for all required approvals
- Instructions for completion (top or reverse side)
- Form revision history in footer

### 2.3 Data Entry Fields

**Required Elements:**
- Entry fields clearly labeled
- Units specified (e.g., "Temperature (°C)", "Weight (kg)")
- Acceptable ranges indicated where applicable
- Date format specified: DD-MMM-YYYY
- Signature blocks include: Signature, Printed Name, Date

## 3. SPECIFICATION TEMPLATE

### 3.1 Starting Material Specification

**Required Sections:**
1. Material Name and Code
2. Description (physical appearance, properties)
3. Supplier Information (approved suppliers list)
4. Pharmacopoeial Reference (if applicable)
5. Storage Conditions
6. Sampling Instructions
7. Test Methods and Acceptance Criteria
8. Re-test Date/Expiry
9. References
10. Approval Signatures

### 3.2 Finished Product Specification

**Required Sections:**
1. Product Name and Code
2. Pharmaceutical Form and Strength
3. Formula Reference
4. Description (appearance, packaging)
5. Quality Characteristics:
   - Identity tests
   - Assay (cannabinoid content)
   - Impurities and degradation products
   - Microbial limits
   - Physical parameters (moisture, particle size, etc.)
6. Storage Conditions and Shelf-Life
7. Packaging Details
8. References (Regulatory dossier, Ph.Eur. monograph)
9. Approval Signatures

---

## 4. BATCH PRODUCTION RECORD (BPR) TEMPLATE

### 4.1 Required Sections (per EU GMP 4.20)

**Section 1: Batch Information**
- Product name and batch number
- Batch size
- Manufacturing start and completion dates
- Responsible persons (operators, supervisors)

**Section 2: Starting Materials**
- Material name and code
- Batch/lot number
- Quantity required vs. actual weighed
- Verification signatures

**Section 3: Manufacturing Steps**
- Step-by-step processing instructions (from Master Formula)
- Equipment used (ID numbers)
- Critical process parameters (time, temperature, speed)
- In-process control results
- Operator initials for each step
- Line clearance checks

**Section 4: Yields**
- Theoretical yield
- Actual yield
- Yield reconciliation (acceptable range)

**Section 5: Deviations and Notes**
- Any deviations from Master Formula
- Justification and authorization

**Section 6: Review and Approval**
- Production Manager review and signature
- QA review and signature
- QP review and signature (for batch release)

## 6. VALIDATION REPORT TEMPLATE

### 6.1 Required Sections

1. **Title Page**

   - Approval signatures

2. **Executive Summary**
   - Pass/Fail statement
   - Key findings

3. **Introduction**
   - Reference to protocol

8. **Recommendations**
   - Follow-up actions
   - Revalidation schedule

9. **Appendices**
   - Raw data

   - Deviation records

## 8. DEVIATION REPORT TEMPLATE

### 8.1 Required Sections

**Section 1: Deviation Identification**
- Deviation number (auto-generated)
- Date and time of occurrence
- Reported by
- Department/area
- Related batch/product (if applicable)

**Section 2: Description**
- What happened (factual description)
- What was expected (SOP reference)
- How was it detected

**Section 3: Immediate Action**
- Containment measures taken
- Product/material impact
- Notification (who was informed)

**Section 4: Investigation**
- Root cause analysis (5 Whys, Fishbone, etc.)
- Contributing factors
- Similar occurrences (trend review)

**Section 5: Impact Assessment**
- Product quality impact
- GMP compliance impact
- Patient safety risk
- Risk level (Critical/Major/Minor)

**Section 6: Corrective and Preventive Actions (CAPA)**
- Immediate correction
- Long-term corrective action
- Preventive actions
- Responsible person and due date
- Effectiveness check plan

**Section 7: Approvals**
- Investigated by: [Name, Signature, Date]
- Reviewed by: [QA Manager, Signature, Date]
- Approved by: [QP/Quality Manager, Signature, Date]

## 13. GENERAL TEMPLATE REQUIREMENTS

### 13.1 All Templates Must Include

**Mandatory Header Elements:**
- Document title
- Document code (unique identifier)
- Version number
- Effective date
- Page numbers (X of Y format)

**Mandatory Footer Elements:**
- Facility name: Purely Plant Medical Cannabis Production Facility
- Document code
- "CONTROLLED COPY" or "UNCONTROLLED COPY" designation
- Confidentiality statement (if applicable)

### 13.2 Document Formatting Standards

**Colors:**
- Black text on white background (for printing clarity)
- Color coding permitted for forms (e.g., critical fields in red boxes)

**Tables:**
- All tables must have clear column headers
- Borders visible for data entry fields
- Adequate row height for handwriting (minimum 1 cm)

**Signature Blocks:**
- Minimum size: 5 cm wide × 2 cm high
- Include: Signature line, Printed Name line, Date line
- For wet-ink signatures: original blue ink preferred

### 13.3 Version Control Elements

All templates must include Revision History table:

| Version | Date | Sections Modified | Description | Author |
|---------|------|-------------------|-------------|--------|
| 1.0 | [Date] | All | Initial release | [Name] |

## 14. TEMPLATE STORAGE AND ACCESS

**Location:**
- Electronic templates stored in: [DOCUMENT_STORAGE_LOCATION]/Templates/
- Access: Read-only for users, edit access for QA Manager only
- Master templates maintained by QA Manager

**Template Updates:**
- Templates reviewed every 24 months
- Updates require QA Manager approval
- Template changes communicated to all document authors
- Users must always use current version of template

---

## 15. TEMPLATE COMPLIANCE

**Deviations from Templates:**
- Minor formatting deviations acceptable if justified (e.g., table size, section order)
- Content section deviations require QA Manager approval
- Regulatory-required sections (per EU GMP) may NOT be omitted

**Template Validation:**
- New templates validated before release
- Validation includes: usability testing, regulatory compliance review, trial use
- Validation documented in Template Validation Report
